# 賽事備份與還原

主管理員可在管理後台下載 `pk-admin-backup-v1` JSON。檔案包含目前賽程、
已確認成績、既有實際開賽紀錄與操作歷程摘要，含私人選手資料，應另存在賽務電腦。
請在首次發布、每輪成績核對及重排確認後下載，至少保留不同日期的兩份備份。
這是手動應用資料備份，沒有自動排程，也不是完整資料庫備份。

檔案不包含登入權限、工作階段、CSRF、網站環境秘密、原始上傳文件、PDF或逐球操作歷程。
已確認的逐局結果包含在賽程資料。操作歷程摘要供查閱，沒有完整舊版賽程快照。
大量資料超過8MB或一萬筆歷程時須使用平台資料庫備份。

## 還原

1. 先下載目前備份，保存操作前的資料。請先結束進行中的比賽並清空或儲存草案。
2. 在原網站的「賽事資料備份與還原」選擇備份JSON，填寫還原原因。
3. 預覽檔案時間、場數、已完賽數、逐場前後差異及賽事設定差異。
4. 確認差異，勾選了解資料取代的選項，再按「確認還原並發布」。
5. 核對後台資料及選手頁面的同步狀態。同步失敗時資料仍已儲存，使用重試同步，不要重複還原。

只能還原原網站的備份。現站已有賽事時，選手、場次與場地識別須相同；不能用來覆蓋另一個賽事。
進行中的比賽、尚未確認結果的完賽紀錄、衝突排程、過期或已使用的預覽均會被拒絕。
備份校驗碼僅檢查檔案完整性，不是數位簽章，不能驗證發行者。只使用自行保管的可信備份。

還原保留現站登入設定與現站操作歷程，新增一筆由目前操作者簽記的還原紀錄。
不會把備份摘要中的操作者當作現站新操作。還原建立新的雲端版本與較大的發布序號，
不倒轉發布序號，也不直接複製舊的發送佇列。

## 災難復原界線

仍有網站環境設定、主管理員身分及儲存連線時，可預覽並確認還原至尚未匯入賽程的空白D1。
這不會重建已刪除的網站、D1/R2資源、帳號權限或秘密。
如果前台R2已保存比備份更新的發布，空白D1無法只從舊備份推知那個發布序號；
此時須核對最新備份與平台復原紀錄，不能把前台「仍保留新資料」當成舊資料還原成功。
平台層備份、保留天數與資源復原演練仍須另行配置。

驗證使用獨立Miniflare資料庫，包含先登錄成績再回復舊備份，以及清空應用資料後還原；
不對正式站寫入演練資料。
