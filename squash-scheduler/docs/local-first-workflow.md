# 地端編排與雲端現場操作

地端負責建立賽事、匯入名單與簡章、確認規則、抽籤、排程及產生文件。
既有兩個 Sites 網站負責現場管理與公開查詢。此架構不需要額外的雲端 Python 服務。

## 啟動地端

安裝 Python 3 與 uv。在專案根目錄執行：

```sh
python3 scripts/start_local.py
```

Windows 可以執行 `START-LOCAL.cmd`；Linux／macOS 可以執行 `sh START-LOCAL.sh`。
首次啟動會安裝鎖定依賴及所需的 Python 3.13。開啟 `http://127.0.0.1:8765/`，並保留命令視窗。

預設工作區為 `squash-scheduler/tournaments/local-event`。新賽事請另用資料夾：

```sh
python3 scripts/start_local.py --workspace squash-scheduler/tournaments/another-event --port 8766
```

已有工作區會直接開啟操作台；頁首「建賽與雲端交換」連結進入 `/setup`。
建立功能不會覆蓋既有賽事。來源檔、名單、字型、賽事與輸出均留在地端，不加入 Git。

PDF 列印在 Windows 可使用已安裝的 Edge；其他環境須先在 `squash-scheduler` 執行一次：

```sh
uv run python -m playwright install chromium
```

## 從檔案到賽程

1. 上傳 `.xlsx`、`.docx` 或文字型 PDF。Excel 使用「姓名」「組別」欄位；只有姓名欄時可在核對畫面補上組別。舊式 `.xls`、`.doc` 請先另存新格式。
2. 查看來源文字、解析警示與候選報名列。可修改、刪除或手動補列。PDF 簡章原文供核對，規則須在表單明確確認，不自動推定條文。掃描 PDF 會要求先做 OCR，不會當作空名單成功匯入。
3. 核對跨組身分。同名預設分開，確定為同一人時才選擇相同身分。確認各組分類、賽事名稱、日期、場地、比賽時間、休息與計分規則。
4. 填寫操作者與原因，預覽後確認建立。原始檔及核對後的報名列會歸檔；只讀取或預覽不會建立賽事。
5. 到「逐組賽制」確認各組賽制。淘汰賽須建立抽籤提案並另行確認籤表。
6. 預覽排程、處理衝突，再確認套用。可使用既有選手負荷與批次賽程調整功能。
7. 在 `/setup` 匯入允許嵌入且涵蓋中文字的 `.ttf`、`.otf` 或 `.ttc` 字型，再由操作台產生 PDF、Excel 與離線閱讀頁。文件仍執行原有 QA；缺少必要規則或素材時會列出問題。

建立後仍可在 `/setup` 的「補齊簡章條文」修改遲到、棄權、傷退、雙方棄權、替補、排名分母及多人同分條文。
先預覽前後差異再確認，已開賽場次保留固定規則；修改後需重新產生文件。

一人、兩人組須另外明確確認處置。一人組可保留名單而不編排競賽；兩人組可確認直接對賽，
核准紀錄綁定該組實際報名。系統不會自動合併組別或刪除報名。

待核對檔案保存在服務記憶體中，重啟前請完成建立。建立後的資料會持久保存。

## 送到雲端與取回

此版本使用手動 JSON 檔交接。下載或地端確認都不會直接修改線上網站。
雲端後台交接功能已於 2026-11-25 隨管理後台第 27 版部署。

### 首次送到雲端

在地端 `/setup` 選「下載雲端賽程 JSON」，由主管理員在雲端首次匯入，再預覽並確認發布。
檔案使用既有 `pk-schedule-v1` 契約。已初始化的後台不允許用首次匯入覆蓋原賽事。

現有雲端契約要求 Asia/Taipei、全賽事最低休息 60 分鐘、每日上限 5 場，以及僅檢查已確定選手。
開賽時間限 08:00–17:30；計分支援三／五局、11／15 分、領先兩分且無上限。
地端可使用較保守的所有可能晉級者模式，但此模式無法交接到目前後台。
不相容的資料會阻擋，系統不會自動放寬規則。

### 雲端取回地端

1. 先完成進行中的比賽，或撤銷誤開賽。已結束但缺少成績的場次須先補齊。
2. 由主管理員在雲端「地端與雲端交接」下載回傳檔。
3. 在原地端工作區 `/setup` 選檔，檢查來源版本、賽程前後差異、成績與實際開賽紀錄。
4. 確認後建立地端新版本，再產生更新的文件或調整未開賽場次。

`pk-cloud-return-v1` 保存原地端版本、雲端版本、網站來源、發布序號、已確認成績、實際開賽時間及實際場地。
若原工作區已另行修改，必須先完成版本核對，不能直接覆蓋。
重複回傳、跨網站、改動規則／身分、衝突安排及無效比分會被拒絕。
歷史實際場地缺少證據時會阻擋下載，不推定為預定場地。

### 地端重排回到雲端

取回後下載的檔案會改為 `pk-local-update-v1`，包含取回時的雲端版本及發布序號。
由主管理員在雲端預覽、確認匯入，再另行確認發布到公開網站。
若雲端期間有其他異動，後台會拒絕過期交接檔，須重新取回並核對。

此交接只更新未開賽場次的時間及場地。既有選手、對戰、賽制、鎖定與已確認成績保留。
地端計算得到的新晉級選手不會透過重排檔自動覆寫雲端對戰身分。
逐分操作歷程不移轉，仍保留在雲端；交接保存已確認的逐局比分。
回傳契約尚未包含實際完賽時刻，地端休息與場地占用檢查採第一次下載時刻作保守上界，
並保留原始開賽時間的秒數；求解器占用區間向外取整分鐘。
檢查碼用來檢查檔案完整性，並非網站簽章；請使用從受信任後台下載的檔案。

## 驗證

在 `squash-scheduler` 安裝開發依賴後執行：

```sh
uv sync --frozen --extra dev
uv run python -m pytest -q tests/test_intake.py tests/test_local_workflow.py tests/test_local_workflow_http.py tests/test_local_workflow_font.py tests/test_local_workflow_rules.py tests/test_local_workflow_small_groups.py tests/test_cloud_handoff.py tests/test_cloud_live.py
```

雲端測試的建置、純函式及隔離 D1 測試方式見 `sites/squash-admin/README.md`。
`test_cloud_handoff.py` 含實際 JavaScript 回傳檔到 Python，再由 JavaScript 核對地端更新的測試。
執行前須依後台 README 建立 `outputs/local-return-model.mjs` 與 `outputs/local-update-model.mjs`；缺少 Node 或 bundle 時該項會跳過。

## 成績、晉級及特殊結果（2026-11-25）

後台以完賽成績登錄為主。正常、棄權、傷退與雙方棄權均先預覽再確認；更正須主管理員填寫原因，
保留舊、新結果。若下游已開打、完賽或鎖定，會阻擋更正。未開賽的衍生晉級身分須重新核對，
到賽程調整發布後，才會顯示下一輪選手。小組名次與同分裁定由賽務明確核定，不從顯示文字猜測。

特殊結果必須先在地端補齊結構化規則，明確選擇是否計入排名、是否實際出賽、雙方積分及排名分母。
單純填寫文字條文不會啟用特殊結果；未核定的類型在後台停用。已交接的賽事可先取回雲端資料，
再核定地端規則，匯出重排交接檔；雲端會另外列出特殊結果類型的前後變更，確認後才開放登錄。
原有局分、選手與計分制式不會經此流程覆寫。前台積分若缺少可計算規則，仍須以地端核定為準。

舊版雲端賽事若缺少晉級來源，可從地端「下載晉級來源核對檔」，在後台核對晉級面板補入同來源資料。
此步只補入明確來源，保留既有場號、結果與安排，不會重建或清空賽事。

備份與還原入口在成績頁下方，僅主管理員可使用；操作見後台 `docs/backup-restore.md`。
這是手動應用資料備份，仍需另外保存原始檔、地端工作區及正式匯出文件。

## 教練版逐組建賽與現場操作（2026-11-26）

啟動專案根目錄 START-LOCAL.sh（Windows 使用 START-LOCAL.cmd），進入 http://127.0.0.1:8765/setup。逐組建賽先輸入組名與每行一人的名單；同名跨組選手要勾選沿用身分，再選賽制、產生籤表、交換籤位並確認對戰。各組完成後調整整體排程並交接雲端。

教練競賽規則須透過預覽確認套用。新籤表交接會附上正式冠軍場次；舊雲端資料可在「賽事工具與資料交接」中核對冠軍場次並預覽套用，發布後供前台使用。既有完賽與進行中場次不改局數。若雲端選定冠軍場次與地端正式籤表不符，取回地端會阻擋，應回到原工作區核對。

現場在「賽程安排」按場次後的場地按鈕加入佇列，每場地最多三場。可上下調整、更換場地或移回清單；隊首顯示目前時間，原定日期時間作進度參考。在「成績登錄」直接填每局分數或選擇棄賽並登錄，畫面不換頁；完成場次移至旁邊，主管理員可更正。修改衝突時保留輸入，重新核對最新成績後再送出。
