# 本地賽務操作

從專案目錄雙擊 `START-OPERATOR.cmd`，啟動後開啟 <http://127.0.0.1:8765/>。這是獨立的八人虛構國中組，可練習設定種子、抽籤與登錄比分。關閉視窗或按 Ctrl+C 可停止服務；重新開啟會保留已儲存的賽事版本。

`START-FULL-ROSTER-OPERATOR.cmd` 在 <http://127.0.0.1:8766/> 開啟另一份 147 筆報名、17 組、279 場的原始名單操作示範。名單來自提供的 Word；其籤位、時間及種子仍為模擬設定，不能當作正式賽程。兩份工作區在 `output/operator-demo-final/`，原交付與原始文件不變，預設匯出均採 PDF 模板 2.2.0。

## 種子與主賽

選擇組別，進入「種子設定」。選擇無種子或提供名單；每位種子需填序號、選手與允許籤位。多個允許籤位以逗號分隔，不會自行套用未提供的種子分離規則。

填寫操作者與異動原因，預覽後確認儲存。設定有變更時，原抽籤會失效；接著預覽主賽抽籤、確認籤表並更新對戰，最後預覽重新排程並確認。同樣的設定不會使既有籤表失效。已開打、有成績或鎖定籤位的組別不能直接改種子。

## 登錄與更正成績

操作台右上角的「即時閱讀頁」可開啟 `/live/`。同時保留兩個視窗，確認儲存比分後，閱讀頁會在下一次成功同步時更新比分與淘汰賽晉級，不須重新匯出。預覽或未確認輸入不會同步。資料來源與使用範圍見 [即時閱讀頁](live-reader.md)。

在「成績登錄」或總覽選擇場次，核對姓名、時間及球場，填寫各局比分。正常完賽會依已輸入局數標示勝方；不補寫未打的局。預覽頁會再次顯示雙方與比分，確認後才儲存。

更正成績會保留原結果。若更正會影響已開打的下游比賽，沿用既有領域檢查並拒絕自動更正。棄權、中途退賽、雙方棄權仍須符合該賽事已明訂的結果與積分規則，介面不會代擬規則。

## 鼓勵賽

「鼓勵賽」逐人顯示符合、不符合或待確認及原因。種子、首輪輪空、棄權／未到場會依確認規定排除；種子或首輪結果未明時不能產生抽籤。資格完整後可預覽籤位、對戰與輪空，再確認套用並重新排程。詳細規則見 [鼓勵賽資格](encouragement-rules.md)。

## 版本與匯出

「場地看板」依場地 A–D 顯示待賽、已叫號、進行中與完成。叫號、開賽及延誤均需預覽確認，不會僅依時鐘推測已開賽。開賽前檢查對手、場地占用、休息與下場衝突；開賽預覽超過兩分鐘須重新產生。登錄延誤後可檢視影響並局部重排。

「名單異動」可登記候補、提出退賽或候補替補、確認影響，再預覽局部重排。每一步均保留操作者、原因與版本；未明訂棄權規則的真實賽事會拒絕代入假設。請先用 [獨立現場演練](live-operator-demo.md) 練習。

「操作歷程」顯示時間、操作者、原因及變更前後差異。復原會建立新草稿，歷史版本完整保留；已有開賽、成績或鎖定排程時，須走成績更正及局部重排流程。

## 人工調整與重排變更預覽

開啟 <http://127.0.0.1:8768/#schedule>，或完整名單的 <http://127.0.0.1:8766/#schedule>。若先前服務仍在執行，重新啟動後再重新整理，載入新增的前端資源與後端操作。

1. 在「賽程調整」用日期、場地、組別、姓名或場號找場次。桌面先顯示四場地時間表，可切換清單；手機使用清單，直接勾選每場左側方框。
2. 可全選目前篩選的可調整場次，或跨日期、場地勾選多場。一次輸入平移分鐘（例如 `15` 延後、`-15` 提前），或批次改日期／場地；剛好選兩場時，可「互換兩場安排」。選取數包含切換篩選後暫時看不到的場次。點場次內容則就近開啟單場編輯，欄位修改後自動加入草案。
3. 待套用場次以標記及色條顯示，滑鼠移入可看原／新安排；「復原上一步」可撤銷最近 30 次草案修改。底列固定顯示變更數，「查看變更」可核對、移除單場或清空，並修改預設的「人工調整賽程」原因。尚未確認時不改賽事資料。
4. 點「檢查 N 場變更」，逐場對照原／新日期、時間、場地及預定打完時間，明列哪些欄位改變。自動重新排程及延誤／異動的局部重排，也使用同一份對照。
5. 檢視原有衝突如何變化：「已排除」、「新增」、「仍存在」。休息不足會列出選手、前後場號、實際預定間隔及所需分鐘；仍存在但間隔改變的衝突保留前後明細。
6. 全部通過才可確認。套用後閱讀頁在下一次成功同步更新；「已套用的異動紀錄」可重新開啟對照，下載當次公告文字。

有衝突的草案仍可閱讀及下載，但確認按鈕停用，後端也拒絕直接確認。必須整份草案通過檢查才會建立新版本；不會只套用其中一部分。交換兩場場地可一起加入草案驗證，不必先保存暫時撞場的中間狀態。

批次操作依目前草案位置計算；如果選取中有鎖定欄位、不支援的未排程場次，或平移超出既定賽期，整次批次動作不加入草案，先前編輯仍保留。時間表的高度按原場次的比賽及場地緩衝時間繪製；重疊安排分欄顯示，所有休息、資格及場地衝突仍以「檢查變更」的完整驗證為準。未提供拖曳操作。

保留固定賽期、球場可用時段、時間格、休息／換場、每日場數、資格依賴、現場占用與鎖定規則，不改籤表或成績。已開打／完成場次不得移動，部分鎖定的欄位保留原值。時間一律依賽事時區解析；瀏覽器時區不同也不改變排定日期。日期選單不提供增加天數。

頁面明示本工作區正在使用的休息基準與每日上限。若舊工作區尚未設定每日上限，會顯示「尚未設定」；不能把該預覽誤認為已通過 4 場／60 分鐘政策。先前完整名單的兩天負荷衝突及未套用新賽程的狀態不因本功能改變，見 [負荷稽核](live-operations.md#選手每日場數與最低休息)。

預覽與草案綁定工作區、來源版本及內容。其他操作先儲存時，舊預覽不能套用；頁面保留待檢視草案並提示依新版本重建。取消預覽會保留草案。草案安排與原因會自動保存在同一瀏覽器及服務網址下，重新載入後可選擇「恢復已保存草案」；已套用的對照保存在不可變版本與操作紀錄中，重啟後可查看。

### 草案自動保存與恢復

「賽程調整」上方會顯示保存狀態；看到「已自動保存於本機」才代表最新編輯已保存。保存內容只有場次、日期時間、場地、原因及來源版本，不保存操作者或操作憑證。復原歷程及選取／篩選只保留在目前頁面。

重新載入會先提供「恢復」、「查看」或「丟棄」；不會自動恢復或套用。來源版本已變、場次不存在或鎖定不相容時，停用恢復，仍可檢視／丟棄。有未確認編輯時，重新整理或離開會觸發瀏覽器提醒。正式確認排程或清空草案後會清除相應保存；切換工作區會保留原工作區的草案，回來後可恢復。

多分頁同時修改時，系統停止自動覆寫，保留本頁編輯，提供檢視其他分頁草案及明確取代保存的操作。若本機儲存被封鎖、空間不足或缺少安全寫入能力，畫面會提示失敗並保留本頁編輯，不能視為已保存。這是目前瀏覽器的本機保存，清除瀏覽器資料會移除草案，也不會同步到另一台電腦或另一個連接埠。

實際 Edge 驗收：`output/draft-storage-final/report.json`；重跑可執行 `.venv\Scripts\python.exe scripts/check_schedule_draft_storage.py --output output/<新的驗證資料夾>`。

下載的 TXT 明確標示「草案」或「公告」、時區、場號、對戰、原／新安排及適用版本。操作者、內部異動原因與驗證細節留在操作資料，不帶入公告。下載不代表對外發布或主辦正式核准；既有 PDF／離線閱讀頁仍需重新匯出才反映變更。

驗證指令：`.venv\Scripts\python.exe scripts/check_manual_schedule.py --output output/<新的驗證資料夾>`。新版證據在 `output/schedule-ux-final/report.json`，涵蓋多選平移、批次換場、復原、篩選保留選取、手機清單、禁止增加賽期、衝突拒絕確認、原子互換、過期版本、公告及閱讀頁同步；1440／768／390px 共 15 張截圖。完整名單版面另見專案根目錄 `.taste-skill/schedule-ux-final/`；inspect 為 0 FAIL、1 WARN，警告為時間表未偵測出資料色彩，實際僅時間文字與待套用變更使用青色，避免把未修改場次標成異動。

完整 279 場／17 組的操作抽查另存 `output/schedule-ux-full-roster/report.json`，驗證三種寬度的標籤多選、平移與復原、手機 44px 勾選熱區與單場自動加入草案。沒有 JavaScript 錯誤或整頁橫向溢出，原工作區內容雜湊不變；本機首次顯示約 2.2 秒，屬單次觀測。

```powershell
.venv\Scripts\python.exe scripts/check_manual_schedule.py --output output/my-manual-schedule-check
```

這個命令操作獨立虛構複本，輸出資料夾須尚不存在。100 項相關 pytest 通過，包含固定賽期內跨日期調整及 60 分鐘休息阻擋；結果在 `output/verification/manual-schedule/pytest.xml`。Ruff、142 份格式與 51 個來源模組 mypy 通過，taste-skill lint／inspect 為 0 FAIL、0 WARN。本輪屬賽務操作與前端增量驗證，沒有重跑完整 PDF 回歸。

每次操作先計算預覽，不寫入賽事；確認時再次檢查來源版本。若其他操作已儲存新版本，原預覽失效，須重新整理，不能套用舊畫面。

「產生 PDF、Excel 與閱讀頁」會在背景建立當時版本的草稿，完成後提供下載入口。匯出失敗會顯示原因，未完成的文件不提供下載。不同版本的匯出分開保存，不會自行正式發布。

匯出紀錄會保存在工作區，重啟後重新核對文件及雜湊。中斷或損毀的匯出會保留失敗紀錄，不提供下載。

「資料備份」下載 ZIP，包含賽事資料、完整版本、來源、字型與操作紀錄，**不含匯出文件**。上傳備份後先檢查內容與檔案完整性，確認才建立獨立還原工作區，原工作區保留不動。可明確切換到還原工作區或切回原工作區；切換會使未確認預覽失效。還原後若要 PDF、Excel 或閱讀頁，請重新匯出。

操作頁需要本機服務；匯出的閱讀頁仍可離線開啟。此版只綁定 `127.0.0.1`，不提供跨電腦共同操作或登入帳號。

若要啟動其他工作區：

```powershell
.venv\Scripts\python.exe -m squash_scheduler serve --workspace <賽事工作區> --port 8765
```

## 選手負荷與衝突總覽

啟動更新後的服務，開啟 <http://127.0.0.1:8766/#workload>（完整名單）或 <http://127.0.0.1:8768/#workload>（虛構演練）。看板預設使用「4 場／60 分鐘試算」，可切換「目前賽事規則」；試算不儲存政策、不重排場次，也不會默默替舊工作區啟用新限制。

1. 使用組別、姓名／場號搜尋、日期及問題類型縮小範圍。預設只列有問題選手；取消勾選可看到全部選手，包含每日零場者。
2. 「已定」為已確定選手身分的出賽安排；「最多」為相容晉級路徑的每日上界，已排除決賽／季軍賽、池內名次等互斥分支，並非預測選手一定打滿。
3. 點選選手查看每日場次、預定打完至下場開打的休息間隔，以及已確定／可能晉級問題。手機會切到明細，按「返回選手清單」返回。
4. 點問題的「選取相關場次調整」，會在賽程頁選取對應場次，跨日期仍保留選取；已開賽、結束或鎖定不可移動的場次會停用調整。修改後先「檢查變更」，整份草案通過才能確認儲存。

看板依已儲存版本分析，尚未確認的草案不計入；草案的改善結果請看「檢查變更」。分析按工作區、版本、內容及政策快取，來源改變則失效；計算中版本更新會拒絕回傳舊報告。分析不完整或資源超限時明示無法判定，不顯示通過。負荷檢查只涵蓋已排有效場次，未排場次與其他場地／資料問題會另外列出，不代表整份賽程通過或可正式發布。

`GET /api/workload?mode=configured|requested` 為操作端介面，仍要求原操作憑證與同源檢查；`requested` 固定為 4 場／60 分鐘，另可指定 `revision_id`、`workspace_id` 核對版本。公開閱讀資料不含這份報告或草案。

完整名單瀏覽器證據：`output/operator-workload-final/report.json`，包含 114 位選手、279 場、篩選、零場者、手機明細、問題跳轉及本機草案保存，原來源與測試複本事件雜湊未變；重跑指令 `.venv\Scripts\python.exe scripts/check_operator_workload.py --output output/<新的驗證資料夾>`。
